# Release gates, test plan and publication checklist

Copying the real implementation retains many small guarantees that an abstract mockup misses. The new event is launch-ready only when all applicable gates pass. Synthetic tests are **not evidence of real tracker availability, real phone GPS or real road access**.

## 1. Source hygiene gate

- Run the skill's read-only `scripts/audit_crow_source.mjs <checkout>` and inspect missing files, manifest assets and old-event markers. It deliberately prints filenames/counts, never secret values.
- Search manually for old event-specific state in files, including non-obvious hardcoded defaults: `35950`, `2026-11-13`, `247`, `133`, `210`, `emily`, `jeff`, `huiyan`, `graham`, `ben`, `meriden`, original public project ID/URL, `PUBLIC_CREW_*`, gold origin, room/localStorage/cache names. Some are human names/art and need deliberate replacements; match context, not blind regex.
- New site identity and D1 are distinct. Raw `#support`, `#locate`, `#crew` capability values never committed. Public share URLs never contain fragment. No old private GPS rows copied.
- Original `guide/index.html` is authoritative. Generated `public/index.html`, `/poster/index.html` and `dist/` regenerated by prebuild; no direct edits that disappear on next build.
- Route and poster asset paths unique and present. No unreleased images in public runner preload/HTML/offline precache. All fixed poster IDs agree across backend/frontend.

## 2. Automated tests

From source checkout:

```sh
npm run install:ci
node --test tests/*.test.mjs
npm run build
```

Don't run install script unless required by environment and approved tooling. Follow the current hosting workflow and owner-specified test host; these are standalone commands, not permission for a forbidden host fallback. Preserve all existing `.test.mjs` files and update event-specific fixtures honestly. ## 3. Synthetic scenario matrix

Use an **isolated room and fixtures** for simulation; never edit live runner reports or fabricate physical race progress in production.

| Scenario | Essential acceptance |
|---|---|
| No race start yet | No default position or bogus pace; correct race date and waiting text |
| Exact bib found, one fix | Individual pin may show, ETA waiting for path |
| Two+ coherent fixes | Route pace/time appear, anchored to GPS and same runner |
| HTTP poll repeated with same fix | Timestamp age increases naturally; ETA does not slide later |
| Older fix arrives after newer | Stored newer report retained |
| Off-route > threshold | ETA disabled, off-route shown |
| Report age crosses 5m | Mark stale, suppress ETA; last seen labelled |
| Runner stops / turns back | No invented forward pace; waiting/stopped reason |
| Runner resumes after a genuine rest | Discard stop-inclusive elapsed time; after >=2 moving intervals and >=~80m compute post-stop pace; early restart pending |
| Tracker has >5min gap | Reset moving pace window; never assume unobserved time was all walking or retain stale speed across a proven stop |
| Runner retired/finished | No onward arrival time |

| Route km 100 vs radial gold | Distinct achievements with appropriate threshold and label |

## 4. Interactive field-phone QA

At minimum test **iPhone-sized 375×667 and 390×844** portrait with simulated slow 3G, offline and normal network; test a real iPhone when one is available. Review both main and poster variants if present.

- Initial hero/map/summary, status strip and bottom controls fit safe areas without overlapping OS bars, tabs, marker labels or poster modal. Text legible outdoors; important actions >44px.
- Dedicated quoted bottom leaderboard tab fits at 375px with the complete label; no floating comparison controls or map-level tracker-age chip. Confirm exact category switch among Female Solo/Male Solo/Pairs/Chained/Other and separately toggle **Emily amongst everyone**—check her informal rank, group labels and 282-entrant live snapshot when that count is applicable (count is dynamic), with no all-category map swarm. Confirm gold step clearly higher than silver even when Emily's portrait is dancing on second. Verify three crows/portrait, colours unchanged when stale, full remaining standings, statuses and family-follow search/list. Toggle an individual followed competitor's Map visibility, confirm stale ghost/last-seen badge and Locate action, test old broad-category map preference never leaks extra markers. Check fresh moving pace, small-screen wrap and reduced motion.
- Person tap opens appropriate sheet (own official pace vs last own GPS vs declared “With runner”), source and age visible. Unknown locations in strip; no fake markers at origin.
- Runner role sees one next point, current milestone/selected WC; supporter role can see all stop options, EV alternates, Met/Skip/Undo and directions if authorized. Unauthenticated Supporting still read-only.
- Pan pauses following; Re-centre resumes and confirms even if already centred. Follow runner/Everyone and WC focused view → Back to meet-up work.
- Hit link to external driving navigation and return. No loss of current point/mode, no unexpected GPS start.
- Connect phones one by one, deny/allow browser GPS, Update once, Start every30s, lock screen/background, return; report age/consent behavior correct. Stop prevents resuming through bfcache.
- Modal intro skipped instantly, paused/resumed, reduced-motion, replayed, missing assets handled. Actual map mounted underneath; accepted queued celebrations wait.
- Simulate new release to one phone; second device syncs, acknowledges, and saved history thumbnail opens correct art. Verify earlier historical originals and *different 80–123 unique scenes*.
- Test Settings Save offline → airplane mode → route and notes visible, service worker update on reconnect with unchanged identity/preferences and no automatic GPS restart.
- Check milestone cards show separate route and crow-flight distances and the installed home-screen icon has the owner-approved background (red in 2026), with consistent SVG/PNG/manifest variants.
- Test location uncertainty on route/park/café/EV/WC buttons and accessible source links. Do not put an unverified point on map just to complete a list.

## 5. Deploy protocol (new event only)

1. Capture current **new Site** project ID, current public version, deployment time, source git revision and D1 schema/migration state; verify correct target before any write.
2. Confirm any unresolved participant, audience, route, timing, portrait, art and award decisions. Honor approval already given for the requested publication; obtain approval only for unresolved choices or actions outside the authorized scope.
3. Run full tests and build in fresh checkout; ensure no unrelated user changes overwritten. Inspect preview with actual phone-size screenshots (record them as *simulated*, not live tracker evidence).
4. If D1 migrations needed, apply sequentially using official Sites deployment path; never erase the race room. Existing generated migrations immutable. Do not blindly reuse previous event D1 database.
5. Publish through supported Sites workflow to **new project**, not historical Crow Crew production. Keep prior deployment available for rollback.
6. Verify live URL anonymous read-only; authorized writer hidden fragment; recovery location grant; no auto GPS; official tracker exact bib/date; stops; landmark text; source/time; milestone manifest and offline worker. Verify real event feed availability separately from synthetic QA.
7. Record version, deployment ID/time, current plan and what remains unverified for crew. Share normal URL only to public, secret invites privately to designated individuals.
8. On regression, stop release, read live state and roll back *code* to known-good deployment; understand D1 migrations separately. Do not reset room or delete history to fix a display bug.
